How it was built

jitmodel: a cryogenic power cycle model, built with Claude

jitmodel is a model and web app for the re-condensing cryogenic power cycle of US Patent 11,598,261 (Just In-Time Energy). LNG or liquid air is pumped to supercritical pressure, heated and expanded, then re-condensed against the incoming pumped liquid in a shared heat exchanger, re-pumped, re-heated and expanded a second time.

It solves the design point of all six patent figures, compares each against a single-expansion baseline, runs parameter sweeps and optimization, and estimates hourly dispatch economics. It was planned and built with Claude. This page links to those conversations and to the project's documents.

The three stages

  1. Planning in Claude on the web

    A conversation on claude.ai covered the patent, the physics and what the app should do. It produced the implementation plan, including the target values from the patent and the order in which to build things.

    Read the planning conversation · PLAN.md (as later revised in the Claude Code session, mainly to switch to a simpler Flask architecture)

  2. Building with Claude Code

    A single Claude Code (CLI) session, run in a development environment inside a Debian Linux Docker container, built the app from the plan in eleven phases, from the fluid property calculations up to the web interface. The phases took a little over two hours (01:27 to 03:45 UTC on September 25, 2026). Results were checked against the patent, and modeling decisions were recorded in DECISIONS.md.

    Read the Claude Code transcript (edited: the prompts and Claude's replies, without tool calls or output)

  3. Improvements and deployment

    In the same session, the web interface was improved (an instructions tab, clearer labels and error messages), and the app was deployed to Google Cloud Run, with Claude giving step-by-step instructions for Google Cloud. At the end, Claude explained how the cycle works and updated the documentation so that a future session can continue the work.
