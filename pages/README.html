jitmodel

A model and web app for the re-condensing cryogenic power cycle of US Patent 11,598,261 (Just In Time Energy): LNG or liquid air is pumped to supercritical pressure, heated and expanded, then re-condensed against the incoming pumped liquid in a shared gasifying/condensing heat exchanger (E-1), re-pumped, re-heated and expanded a second time.

It covers design-point solves of all six patent figures (Figs. 1, 2, 3, 4, 4A, 5), comparison with a single-expansion baseline, parameter sweeps and optimization, and hourly dispatch economics. It is a dev instance only: a single-process Flask server with no authentication.

Freedom to operate. This project models a patented process (US 11,598,261). Commercial use of the process, or of results from this model, may require a license from the patent holder and legal review.

Setup

Debian 13 (or similar). System packages, installed once by an administrator:

sudo apt install -y git make build-essential ca-certificates python3 python3-venv python3-pip python3-dev \
    poppler-utils chromium

Then, inside the repository (nothing is installed outside it):

make setup      # creates .venv (Python 3.13) and installs the package with its dev tools; enables .githooks
make dev        # http://0.0.0.0:5001 — pages, static files and JSON API on one port (dev only, no auth)
Command What it does
make test Test suite (about 160 tests, ~1.5 min; excludes the browser test)
make e2e End-to-end browser test (Playwright driving the system /usr/bin/chromium)
make lint ruff check, ruff format --check, mypy --strict jitmodel/core (also the pre-commit hook)
make format Apply ruff formatting and fixes
make validation Re-solve every preset and regenerate the summary in docs/VALIDATION.md

Every Python package is vetted on PyPI before it is added (see CLAUDE.md). Plotly.js and the IBM Plex fonts are vendored under jitmodel/web/static/, with sources and SHA-256 hashes in docs/DECISIONS.md (D75). Nothing loads from a CDN at runtime.

Using it

The Instructions tab in the app explains the cycle, why it matters, and how to use every tab, including the optimizer. In brief:

  • Flowsheet: pick a preset, adjust the main inputs with the sliders (the E-1 intermediate pressure and its T–Q curve update live), open All inputs for the rest, and press Solve cycle. The diagram colors streams by temperature; click a unit to inspect it. Results show net power, pumps, turbines, heat rate, specific output and the gain over the single-expansion baseline. Save case / Load a saved case keep inputs as JSON.
  • Heat exchangers: T–Q profiles of every exchanger with its pinch, and a T–s diagram with the saturation dome.
  • Sweeps: 1-D or 2-D sweeps over any numeric input (line chart or heatmap), and multi-start optimization of net power or specific output. Click a point to load it into the flowsheet.
  • Dispatch & economics: upload an hourly price CSV (one price column, $/MWh), set the tank and liquefaction inputs, and choose a rule: price threshold, fixed daily windows, or perfect-foresight LP.
  • Units: US customary (the patent’s units) or SI, toggled in the header. Internally everything is SI, and conversion happens only in jitmodel/units.py.
  • Exports: every result has CSV and JSON exports. Results are stored in var/results/ (git-ignored).

Every action works without JavaScript; scripts only add live preview, charts, click-to-inspect and job polling.

How a solve works:

  1. The intermediate pressure is the lowest pressure at which the T-1 exhaust fully re-condenses in E-1 while the minimum temperature difference along the discretized exchanger stays ≥ ΔT_min. The pinch sits just above the hot stream’s dew point, against the supercritical cold stream’s heat-capacity peak (core/intermediate.py).
  2. Because that pressure sits upstream of T-1, it is solved in an outer design loop around the flowsheet.
  3. The flowsheet is sequential-modular: automatic minimum tear-stream selection, bounded Wegstein iteration with backtracking, and a Broyden fallback (core/flowsheet.py).
  4. A converged flowsheet with any temperature cross is reported as infeasible, never as a result.

Validation

docs/VALIDATION.md holds the per-preset checks against the patent (regenerate with make validation). At default inputs every preset:

  • re-condenses within ±10 % of the patent’s intermediate pressure (+0.4 % to +1.5 %; liquid air at −228.8 °F against the patent’s ≈−230 °F);
  • closes its energy balance to better than 1e-11;
  • beats its single-expansion baseline.

Every modeling choice, default and source is logged in docs/DECISIONS.md (D1-D81).

Deploying to Cloud Run

The current deployment (project, region, access) and the step-by-step update routine are in docs/DEPLOY.md.

  • Dockerfile builds the image: Python 3.13, the pinned runtime packages in requirements-deploy.txt, and gunicorn serving the app on $PORT.

  • cloudbuild.yaml builds the image in Cloud Build, pushes it to Artifact Registry and deploys it to Cloud Run:

    gcloud builds submit --config cloudbuild.yaml --substitutions=_REGION=us-central1

  • The service is private by default. Pass _ACCESS=--allow-unauthenticated in --substitutions for a public URL.

  • It runs as one instance with 2 vCPU and 2 GiB, and scales to zero when idle. Saved results are lost when the instance stops (D84).

  • When runtime packages are upgraded in .venv, update the pins in requirements-deploy.txt to match.

Limitations

  • Fluids. LNG is pure methane, which understates the condensing glide of real LNG. Air is CoolProp’s pseudo-pure model: it has a bubble/dew glide but is not a true mixture, and its two-phase flashes need workarounds (D21). Methane is extrapolated above 625 K and states there are flagged (D20).
  • No pressure drops in exchangers, piping or burners. Heat exchangers are specified by duty or approach; UA rating is not modeled.
  • Heat sources are boundary streams. Gas turbines and engines are not modeled as machines (their exhaust, coolant and air are inputs), so engine-side effects such as removing a turbocharger are not captured. Default flows and temperatures are generic, feasible sizings (not vendor data and not optimized). Several defaults leave heat unused; the optimizer is the tool for rebalancing them.
  • Assumed arrangements. The Fig. 4 ORC is not shown in the patent; a methane ORC is assumed (D49). Fig. 4A omits the ORC (D58). Exhaust water condensation is not modeled; exchangers stop at the dew point where flagged (D59).
  • The baseline is the plan’s pump → heat → single expansion, with no recuperator, ORC or fuel. The gains depend on that definition, so compare fuel-burning cases by heat rate as well (D38, VALIDATION.md).
  • Dispatch values electricity only. Part-load scales linearly; the value of stored gas (the point of the patent’s LNG gas-and-power storage cases) is not counted (D65). The test price file is synthetic, not market data.
  • Dev instance only: single process, no authentication, and Flask’s debugger is enabled on 0.0.0.0. Use on a trusted network.
